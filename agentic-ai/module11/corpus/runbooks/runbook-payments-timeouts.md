# Payments authorization timeouts

Use this runbook when card authorizations in payments-service time out or exceed the gateway deadline. Start with the deployment history, because a new synchronous call on the authorization path is the usual cause of a sudden rise in timeouts. Compare authorization latency, the timeout rate and the call latency of every dependency before and after the most recent deployment. Read the payments-service logs for gateway deadline exceeded messages and note which dependency consumed most of the time budget, then quote that line exactly. If a fraud-score or risk call was added to the request path, check whether its client timeout is longer than the remaining gateway deadline. Prefer disabling the new call through its runtime feature switch over a rollback, because the release may have added a database column that newer reports already read. A rollback of payments-service needs the payments release owner and a compatibility check of the ledger schema. Do not restore databases or change payment routing during the investigation; propose the next step, label it as not executed, and record the probable cause in the incident note.
