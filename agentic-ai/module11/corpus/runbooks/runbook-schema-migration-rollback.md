# Rollback after a schema migration

A release that ran a database schema migration cannot be undone by redeploying the previous application version alone. First, read the deployment record and check whether a migration completed, which tables or columns it renamed, and whether a reverse migration exists and was tested. Then list every downstream consumer of the service, because older readers often fail first with errors such as a missing column. Check backup evidence: a pre-migration backup is only usable if a restore test has been completed, and an untested restore must be reported as untested. The usual safe options are a compatibility fix for older readers against the new schema, or a restore from backup tested in isolation with the data loss assessed first. An application-only rollback is unsafe whenever the previous version requires the old schema. Every recovery step here is a proposal for the release owner, who must approve it before anyone executes it, and the plan must say that no changes were made.
